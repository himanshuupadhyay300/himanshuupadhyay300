# Recruiter-focused GitHub profile checklist

## Profile README

- [x] **Who are you?** State your target role, domain and relevant professional background in the opening lines.
- [x] **What do you build?** Describe the engineering problems you solve, not only your job title.
- [x] **What are you working on or learning now?** List current focus areas and label roadmap items honestly.
- [x] **What tools do you use?** Group skills by practical use; distinguish tested hands-on work from templates, design work and learning.
- [x] **What proves your skills?** Feature two or three strong repositories with problem, solution, stack, test evidence and implementation status.
- [x] **How do you engineer?** Show practices such as testing, data quality, idempotency, logging, documentation and independent validation.
- [x] **How can people reach you?** Include LinkedIn and a professional email address.
- [x] **Can a reviewer trust the claims?** Identify synthetic data, unverified integrations, design-only deliverables and work not yet deployed.

## GitHub profile outside the README

- [ ] Set a clear profile bio, e.g. `Automotive Data Engineer | Python · PySpark · SQL | Azure Data Engineering`.
- [ ] Add a relevant location and portfolio/LinkedIn link if you are comfortable making them public.
- [ ] Pin the three featured repositories in the same order as the README.
- [ ] Give each repository a clear description, topics, license, setup instructions, architecture diagram and test/run instructions.
- [ ] Ensure the repository screenshots, badges and workflow indicators reflect their current state; remove broken or unverified badges.
- [ ] Keep the profile README and project READMEs synchronized when implementation status changes.

## What to avoid

- Avoid long lists of tools that are not demonstrated in code or project documentation.
- Avoid implying a cloud service was deployed when the repository only contains templates.
- Avoid describing synthetic examples as production, employer or real-vehicle data.
- Avoid unsupported performance, business-impact or accuracy claims.
- Avoid filling the first screen with visitor counters, streak cards or decorative badges; prioritize projects and evidence.
